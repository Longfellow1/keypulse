# M1 验收报告（2026-10-12）

> 状态：待签收。题目逐题判分以用户为准，下表是技术负责人的预判。
> 题目、标准答案和回答都来自用户本机的真实数据，只保存在本机，不进仓库（`no-real-data-in-repo`）。本报告只写汇总数字。

## 结论

M1 的目标是让 AI 通过 MCP 查询用户本机的工作与生活记忆。在同一宿主（Claude Code）、同一组题目下做对照：接入 KeyPulse 的一组答对 16/19，只用 bash 读本机文件的一组答对 10/19。

- 只有 KeyPulse 答对的有 6 题。
- 只有 bash 答对的有 0 题。
- KeyPulse 组的单题中位耗时是 bash 组的约 1/3。

权限边界、不编造、零泄露、升级安全几项都通过。按原定标准，「不可替代」一条没过，已按实测结果重新定义（D29），原因见下文。

## 怎么测的（D29）

| 项 | 做法 |
|---|---|
| 题目 | 23 道，取自真实数据：采集流 9、超过来源保留期 3、AI 历史与本机已有 7、权限边界 2、无答案 2 |
| 实验组 | Claude Code 无界面模式，只能用 KeyPulse 的 MCP 工具，数据是真实库的副本 |

| 防串题 | 每题不保留会话记录；实验组的库副本删除了出题之后的会话记录 |

**关于②**：原标准是「12 道采集流和保留期题里，KeyPulse ≥10，bash ≤2」。实测 bash 答对了 5 道，原因是出题时分组标错了：Chrome 自带浏览历史，有些文件也还在硬盘上，这几题本来就不是只有 KeyPulse 能拿到。用户决定按实测结果改用上表的标准。这条标准是在看到结果之后定的，特此注明。

**两组都答错的 3 题**：
- 网页标题有，但提问原文没采到；
- 同一天推送过三次，无法判断是哪一次；
- 同一个问题有多次相关记录，答成了另一次。

前两类属于采集面的限制，第三类是检索排序问题，交给 M2 处理。
