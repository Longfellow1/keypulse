# KeyPulse 二阶段产品战略 + 路线图

> 日期：2026-05-03
> 阶段：一阶段（采集 + 沉淀）已完成 → 二阶段（消费 + 智能化）规划
> 形式：开源 macOS app（local-first，数据所有权，hackable）

---

## 一、问题起点

KeyPulse 一阶段把"采集"和"沉淀"做到了 90 分：
- 采集层：键盘 / window / AX text / OCR / clipboard / manual marks 全覆盖
- 处理层：normalizer → pipeline → surface snapshot → narrative engine
- 存储层：SQLite + Obsidian markdown vault
- 展示层：HUD（状态栏） + Daily report（Markdown）
- 配置层：~/.keypulse/config.toml + secrets.env + setup CLI
- 运维层：launchd daemon + health check + obsidian-sync

但**消费侧只有 20 分**：用户拿到这些数据后能干什么，没有被设计。

用户提出的灵魂问题：

> **"怎么把『我（用户）』的个人行为、习惯数据提炼成思想、方法、经验？"**

这是二阶段的核心命题。

## 二、中观评审（产品判断）

### 2.1 病灶诊断

| 病型 | KeyPulse 的具体表现 |
|---|---|
| **万能入口症** | HUD 一个小窗承载状态/数字/提示/今日意图/暂停/重启/陪伴感 6+ 类信息，每一项都不是用户每天必须看的杀手场景 |
| **技术炫技症** | 采集端齐活了 — 键盘/window/AX text/OCR/clipboard/manual — 但每条采集源对用户的边际价值都没单独验证 |
| **场景错配症** | daemon 7×24 跑高频采集，但用户消费这些数据是低频（一天打开 HUD 1-2 次），生产/消费节奏严重错配 |
| **指标幻觉症** | HUD 顶部"有效 48 / 过滤 13"—— 用户看了能干什么？没有连接到任何 next action |

**最致命的不是上面任何一个，是 — 消费侧空白**。

### 2.2 关键假设审讯（用户价值 = 新体验 − 旧体验 − 替换成本）

| 假设 | 证据等级 | 状态 |
|---|---|---|
| A1: 我需要被动记录的工作流 | L1（用户自述）| 旧体验是 Apple Screen Time / git log / Obsidian 手写 — 哪个被替代了？ |
| A2: LLM 筛选的"有效"内容比我自己写更有价值 | L0 | 未验证。LLM 漏的多还是替你省的多？ |
| A3: 我会每天打开 Obsidian 看 KeyPulse 的 daily notes | L0 | 未验证。用了 N 天后还会去看吗？ |
| A4: HUD 打开率 / 打开后的行动 | L0 | 没在追踪。这是判断 HUD 价值的关键先行指标 |
| A5: Obsidian sink 是手段不是目标 | L1 | 用户已承认 → 核心 sink 不确定意味着整条管道下游悬空 |

**证据-投入失配**：证据 L0~L1，投入 Large（多月开发、复杂技术栈）。如果是 hobby 心态 OK；如果想给别人用，是组织赌博。

### 2.3 失败预演

#### Path A · 自娱（用户自己用）
- Month 1-2：每天看 HUD 觉得新奇
- Month 3：偶尔打开 Obsidian 看 daily notes，但不是每天
- Month 4-5：HUD icon 还在状态栏，不主动点开；daemon 默默跑，磁盘慢慢涨
- Month 6+：仍在跑，但是后台数字噪音
- **根因**：HUD 看了无决策可做，Obsidian 看了无后续动作 — 没有杀手消费场景

#### Path B · 上架/给别人用
- Month 1：少数 Obsidian 重度用户安装
- Month 2：留存崩 — ① 配置门槛 ② "看了能干什么"问号
- Month 3-4：反馈集中在"漂亮但不知道用来干嘛"
- Month 6+：GitHub star 几百、DAU 个位数
- **根因**：采集 → 沉淀 → ??? → 用户行动改变，中间那个 ??? 从未设计

### 2.4 判决

| 场景 | Verdict |
|---|---|
| 用户自己 hobby 心态 | **BUILD** — 继续做没问题，但承认是 hobby，不要持续投入"功能扩张" |
| 想给别人用 / OSS 推广 | **REFRAME** — 不是 KILL，因为底层管道扎实；但产品定位要从"被动采集 + 沉淀"重写为"被动采集 + 触发用户行动" |

## 三、独立思考：数据 → 智慧的提炼路径

### 3.1 关键拆解

| 层级 | 怎么形成 | 系统能扮演什么角色 |
|---|---|---|
| **经验** | 单次事件 + 结果 + 回顾 | 提供"事件+结果"的可信记录，**触发回顾时机** |
| **方法** | 多次事件中识别模式 + 抽象 + 验证 | 帮你看见**跨时间的模式**，提出抽象 |
| **思想** | 长期观察 + 认知综合 | 提供**纵向镜子**，让用户看见自己看不见的自己 |

KeyPulse 当前停在「事件 + 短时主题」层级，**没到模式，更没到方法/思想**。

### 3.2 核心判断

**数据不会通过更好的组织变成智慧。数据变成智慧的瞬间，是它跟用户的自我叙事发生冲突的瞬间。**

人对自己有一套叙事：
- "我是早起型选手"
- "我专注的时候不刷手机"
- "我做 X 的时候效率高"

**这些叙事大半是错的，但用户从不会知道** — 因为没有镜子。

KeyPulse 二阶段不应该是更精致的"展示"或"沉淀"，而应该是**有意识地、温柔地、不断地用真实数据撞击用户的自我叙事**。这个撞击发生时，用户大脑里会自己生出方法和思想 — **系统的工作是制造撞击**。

### 3.3 产品形态对照

❌ **错的形态**（当前）：
- "你今天打了 500 个字"（镜像）
- "你在写 X 主题"（分类）
- "看你今天的智能总结"（digest）

✅ **对的形态**（二阶段）：
- **信念 vs 现实**："你说你早上效率高，但本月数据显示下午 3-5 点的有效产出比上午多 40%。这个叙事要更新吗？"
- **承诺审计**："上周你立的 flag『11 点前睡』被打破 4 次。仍然坚持这个原则吗？"
- **模式提问**："你这个月每次打开 Twitter 后平均 32 分钟才回到工作。这是你想要的吗？"
- **假设驱动**："假设：你在听 [音乐] 时写作产出更高。要追踪一周验证吗？"

### 3.4 三层机制

要做到上面那个形态，系统必须新增三个机制层：

1. **声明层** — 让用户能写下"我相信"和"我承诺"
2. **比对层** — 持续把声明跟真实数据对照（后台跑，不打扰）
3. **撞击层** — 在合适时机把比对结果**问句式地**端到用户面前

**关键：撞击是问句式，不是结论式。**用户的回答（保持/更新/否认）就是新的"思想"。

## 四、价值交换设计（俞军视角调用）

### 4.1 俞军方法论核心

1. **用户模型五属性**：异质性、情境性、可塑性、自利性、有限理性
2. **交易模型**：用户每次使用 = 一次交易，付出（时间/认知/隐私/操作）换价值
3. **用户价值 = 新体验 − 旧体验 − 替换成本**

俞军会用三个动作砍方案：
- **"用户什么时候来？"**（情境性）→ KeyPulse 现在让用户自己想起来打开，**情境驱动 = 0**
- **"这次交易，他付出什么换什么？"**（交易模型）→ "看日报"用户付出 30 秒注意力得 0 决策价值，**赤字**
- **"他下次为什么再来？"**（可塑性）→ 当前没有让用户行为被产品塑造的钩子

俞军不会先想 feature，**他会先列一张"用户在什么情境下需要什么"的二维表**。

### 4.2 情境-价值二维表

| 用户情境 | 真正想要的 | KeyPulse 能交付什么 | 交易类型 |
|---|---|---|---|
| **早上刚开 Mac** | 快速恢复昨天工作流 | "你昨天最后停在 `app.py:180`，要继续吗？" | **白嫖型** ⭐ |
| **任务切换回来** | 找回打断前的上下文 | "你刚才在写 X，相关 5 个 tab + 2 个文件已恢复" | **白嫖型** ⭐ |
| **想找一段记忆** | 模糊查询自己的信息流 | 个人知识检索：搜"那个讲 hooks 的网页" | **白嫖型** |
| **周五下午** | 不想从零写周报 | 自动出周报草稿 | **白嫖型** ⭐⭐⭐ |
| **月末/季末** | 不记得自己做了啥 | 季度盘点 | **白嫖型** ⭐ |
| **晚上下班前** | 一份成就感 + 第二天起点 | 30 秒确认草稿 → 沉淀经验 | **小付出大回报型** ⭐ |
| **当下感觉卡住** | 知道自己卡了 | "你打开同一份文档 8 次没编辑，要换个事吗？" | **撞击型** |
| **建立习惯/承诺** | 让承诺有人盯 | "你说不超 30 分钟 Twitter，今天已 47 分钟" | **撞击型** |
| **想了解自己**（高自省时刻）| 看见盲点 | 信念 vs 现实 | **撞击型**（远期）|

⭐⭐⭐ = 杀手交易；⭐ = 高价值

### 4.3 三种交换机制

#### 1. 白嫖型（系统先给，用户 0 成本）
- **用途**：开局建立信任，让用户养成"系统在帮我"的预期
- **例子**：周报自动生成、工作恢复、上下文找回
- **关键**：**情境驱动** — 系统在对的时机出现，不是等用户打开

#### 2. 小付出大回报型（用户 30 秒 → 得 N 倍价值）
- **用途**：长期产品成长的引擎，用户的小付出**反过来训练系统更准**
- **例子**：晚上的复盘草稿 — 用户勾选"对/错/补充"，30 秒搞定 → ① 当天经验沉淀 ② 系统下次更懂他
- **关键**：付出和回报必须紧贴（24 小时内），不能让用户感觉"我喂数据，系统拿去吃"

#### 3. 撞击型（用户付认知 → 得自我洞察）
- **用途**：长期高价值，但门槛高
- **前提**：用户已经经历过 1 + 2，对产品有信任
- **别在二阶段开局做**

### 4.4 关键转折：声明层不好做的解药

用户原话："声明层不好做。"

俞军会说："**因为你想让用户先付出再得到。反过来。**"

**正确顺序**：
1. 系统先白嫖型兑现一段时间（周报、恢复、检索）
2. 用户感受到"哦，它真的在帮我"
3. **此时**系统说："你想让我做得更准吗？告诉我『今天最重要的事』，我帮你跟踪"
4. 用户主动声明，因为他已经看到了系统能用好他给的信息

**当前 HUD 把"今日重要的事儿"放在 hero 是对的设计，但提前了** — 用户还没体验过它能干嘛，写了也没正反馈，必然冷启动失败。

**修正建议**：v1.1 HUD 上线后，"今日重要的事儿"先**降级成可选小卡**，等周报/恢复跑通有信任再升回 hero。

## 五、开源 vs 商业的差异校准

俞军方法论 focus 在商业产品。开源场景下要做差异化调整：

| 维度 | 商业（俞军场景）| 开源（KeyPulse） |
|---|---|---|
| 杀手指标 | DAU / 留存 / 付费 | "git clone 后留下不卸载" + 推荐扩散 |
| 用户群 | 大众/细分 | 开发者 + 极客 + 个人知识管理重度用户（窄但深）|
| 信任来源 | 品牌 + 体验 | 代码质量 + 数据所有权 + maintainer 活跃度 |
| 病毒传播 | 增长团队 | **每个 release 必须有一个"能在 HN/Twitter 上讲的故事"** |
| 替换成本 | 高（迁移痛）| 低（卸了就走）→ **第一周必须 wow** |

**结论**：俞军交易模型仍然成立，但开源场景下"价值兑现"必须更直接 — 商业产品可以靠"长期价值"留人，开源产品如果一周内没让人 wow，那就 uninstall + 删 repo。

### 设计原则（4 条铁律）

1. **每个 milestone 出一个能讲的故事**：能录 30 秒 GIF 上 HN 的那种
2. **README 60 秒原则**：用户读完 README 立刻决定 git clone
3. **数据所有权 + local-first + hackable** 是开源辨识度，不能丢
4. **杀手交易优先于功能完整度**：先做 1 个让人哭着夸的，比 5 个还行的强

### 各 milestone 详细说明

#### M0（已完成）
- 采集 + Obsidian sink + HUD v1.1（Plan A 布局 + ✦ icon + 状态栏 SF Symbol + 重启按钮 + 陪伴 N 天 + 异常分类框架）
- macOS app 打包 + setup 流程
- launchd daemon

#### M1 · 自动周报草稿（4 周）
**目标**：让用户每周五下午得到一份能直接交给老板/自己的周报草稿。

**为什么是杀手**：周报是**最普世的痛** — 每个打工人/学生/独立开发者都要对外解释自己在干啥。周报草稿可以"赌一周"才出一次成果 → 技术上风险小，先跑通端到端。

**子任务**：
- 周报模板设计（项目 / 时间 / 完成事项 / 在学的）
- 数据聚合：从 raw_events + signals + manual marks 拼周报
- 触发机制：周五下午 17:00 自动 macOS 通知
- 质量验收：用户自己用 4 周，每次反馈"够不够直接用"

#### M2 · 早上工作恢复（+4 周）
**目标**：早上开 Mac，KeyPulse 弹"昨天最后在 X 文件改 Y，要继续吗？"

**为什么是杀手**：开发者圈的杀手场景。Time Machine 备份的是文件，KeyPulse 备份的是**心流上下文**。

**子任务**：
- 检测"工作恢复时机"（早上首次解锁 Mac）
- 提取"昨天最后做的事"（最后 30 分钟有效活动）
- 一键恢复（打开文件/浏览器 tab/IDE）
- macOS 通知 + 一个"恢复"按钮

#### M2.5 · 个人记忆检索（+2 周）
**目标**：cmd+opt+space 拉起轻量搜索条，搜历史记忆。

**例子**："那个讲 hooks 的网页" → 翻你 6 月看过的 React tab。

**子任务**：
- 全局快捷键
- 简单搜索 UI
- 索引 + 倒排（SQLite FTS5）
- 结果按时间衰减权重

#### M3 · OSS 收口 + 发布窗口（+1 周）
**这不是技术 milestone，是发布窗口**。

M1+M2+M2.5 跑通 → 已经有 3 个杀手交易 → 这才有底气上 HN。

**发布前必做**：
- README 重写：1 屏 + 1 个 GIF + 1 行 install
- `brew install keypulse`
- `docs.keypulse.dev` 文档站
- CHANGELOG + Release Notes
- Issue / PR template
- Demo 视频 / GIF 资产（每个杀手交易一段）

**不要在功能没到位之前发 "Show HN"** — 开源圈一次失败的发布要等 6 个月才能再发。

#### M4 · 声明层 + 复盘机制（+4 周）
**前提**：M1-M3 已建立用户对系统的信任。

**目标**：晚上 22:00 推送"今日草稿"，用户 30 秒勾选 → 沉淀经验 + 训练系统。

**子任务**：
- 晚上自动生成草稿
- 30 秒交互界面（勾选 + 补充）
- 用户勾选反向 fine-tune 哪些活动算"高价值"
- 沉淀到 Obsidian 的 daily note 末尾
- HUD 上"今日重要的事儿"恢复到 hero 位置（此时有信任基础）

**这是兑现"撞击层"的前置工作**。

#### M5 · 插件式 Sink（+3 周）
**这是 OSS 大招**。

**目标**：让用户把 KeyPulse 接到自己想要的 sink（Logseq、Notion、纯 markdown、自定义脚本）。

**为什么重要**：
- 兑现 memory 里"Obsidian 是过程不是目标"的承诺
- 真正实现"数据所有权"
- 是 OSS 社区贡献的最佳入口（每个用户可以贡献自己的 sink）

**子任务**：
- Sink interface 抽象
- Obsidian 改造为 plugin
- 文档：怎么写自己的 sink
- 第二个内置 sink（Logseq 或 plain markdown）

#### M6+（远期，不排期）
- 撞击型功能（信念 vs 现实、承诺审计、模式提问）
- 位置升级 4 步
- 跨设备同步
- 协作场景（团队 KeyPulse？只在采集端做开源 → 各家自己消费）

| **意图卡（之前砍了又想留）？** | 并入 M4 声明层 | 如果想 M1 就上也行，但会冷启动失败 |
| **HUD「今日重要的事儿」要不要降级？** | 暂不降，等 M4 配套上线一起调整 | 立即降为可选小卡 |

## 八、核心结论

1. **KeyPulse 二阶段不是"功能扩张"，是"杀手交易聚焦"**
   - 商业产品可以做厚做全，开源产品必须做尖做深 — 一锥子扎透才有人记住

2. **M1 + M2 + M2.5 是这把锥子的尖**
   - 这三个跑通，KeyPulse 就从"漂亮但不知道用来干嘛的 hobby project"变成"知识工作者的隐形助理"
   - 这是开源圈愿意为它写博客、推朋友、贡献代码的产品形态

3. **M3 之前别想推广，M3 之后必须推广**
   - 不推广 = 自费做公益

4. **声明层（用户付出）必须在白嫖（系统先给）之后**
   - M4 的"今日重要的事儿 / 给明天的一句话"是基于 M1-M3 的信任建立的
   - 当前 HUD v1.1 的 hero 设计提前了，要在 M4 配套上线时调整

5. **数据 → 思想的路径不是 organize，是 confront**
   - M6+ 撞击型功能是终极形态
   - 但必须等系统已经成为用户日常工作流的一部分才有效
