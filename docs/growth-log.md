## Feedback categories

Use these categories when reviewing issues, comments, DMs, and forum replies:

- README unclear
- install failure
- privacy concern
- Obsidian workflow question
- feature request
- positioning feedback
- praise / resonance
- spam / low-signal

## Stage goals

| Stage | Goal | What it validates |
|---|---:|---|
| 0-20 stars | Warm feedback loop | Friends and peers understand the project |
| 20-50 stars | README conversion | Strangers can understand and save it |
| 50-100 stars | Narrative spread | The positioning travels beyond direct network |
| 100+ stars | Product pull | Users start opening issues, asking questions, and sharing workflows |

## Daily operating loop

1. Check stars, issues, PRs, comments, and README rendering.
2. Categorize new feedback.
3. Update this log when there is a meaningful action or metric change.
4. Pick one content angle from positioning or Obsidian workflow.
5. Do not automate DMs, stars, follows, or forum replies.
