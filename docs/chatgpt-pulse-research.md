# ChatGPT Pulse 调研 + KeyPulse 借鉴策略

**日期**：2026-05-08
**调研方式**：Haiku WebSearch / WebFetch（OpenAI 官方 + TechCrunch + 用户评测）
**目的**：Pulse 是 OpenAI 的 AI native"主动推荐"产品，与 KeyPulse 目标重叠路径不同。本文记录调研结果 + 用 product judgment 视角给出 KeyPulse 借鉴策略建议（非审判）。

---

## 1 · Pulse 是什么

**形态**：ChatGPT 移动端的一个 Tab。每天早上自动推 5-10 张视觉卡片，明示"That's it for today"——**有意的"停止点"设计**，不做无限滚动。Pro 独占（$200/月），目前仅移动端预览，计划逐步下放 Plus / 免费版（受 GPU 容量限制）。

**生成时机**：用户睡眠期间夜间异步生成。

**核心理念**：从"反应式"（用户问，AI 答）转向"主动式"（AI 在用户问之前先想清楚）。

## 2 · 数据来源

| 信号 | 详情 |
|---|---|
| 聊天历史 | 用户过去对话内容 + 提问模式 |
| ChatGPT Memory | 用户保存或标记的偏好信息 |
| 用户反馈 | 卡片 👍/👎 + Curate 指令 |
| Connector | Gmail / Google Calendar，**默认全关闭**，用户主动启用 |
| 实时网络 | 新闻 + 趋势 |

**Connector 关键特征**：默认关、单独可控、随时断开。Calendar 接通后可主动起草会议议程、提醒生日礼物、推荐旅行餐厅。

## 3 · 推荐机制

- **排序算法**：未公开，综合考虑"频率 + 用户反馈权重 + 日历优先级 + 趋势时效"
- **颗粒度**：视觉卡片（图文）+ 可展开详情，**不是长文本报告**
- **可解释性**：部分卡片附源链接，但"为什么推这条"的机制未明示
- **反馈闭环速度**：用户报告 **3-4 天内**能明显感觉系统学聪明了

## 4 · 用户能动性

- **主动调教**：Curate 指令（"我想看周五活动汇总 / 学习技巧 / 体育新闻"）
- **反馈**：单条 👍/👎，删除可恢复
- **生命周期**：Ephemeral（每天刷新），历史回看支持未公开
- **不可调**：推荐深度、话题黑名单（只能针对单条说"不喜欢"）

## 5 · 隐私 / 数据边界

- 处理位置：云端（OpenAI 服务器）
- 训练数据：Pro/Plus 不用于训练公开模型（企业版承诺，消费版条款模糊）
- 数据保留期限：**未公示**
- 安全：AES-256 at rest, TLS 1.2+ in transit
- 用户控制：每条 Connector 单独可切

## 6 · 用户实际反馈

### 正向
- 高管反馈：每天省 1 小时会议准备时间
- 学生反馈：推荐"比对话逻辑步数领先几步"
- 习惯养成快：迅速成为 Morning Routine
- 自适应快：3-4 天系统明显学习用户偏好

### 负向 / 槽点
- **HN**："主动 AI 通知感觉讨厌"
- 推荐重复 / 时有过时建议（如已完成项目仍提示）
- 隐私焦虑（夜间后台处理 + Connector 权限）
- 相比 Advanced Voice Mode 的火爆，**Pulse 评论"更谨慎"**，缺少广泛热情
- 访问门槛高（仅 Pro / 仅移动 / 仅预览）

## 7 · KeyPulse 可借鉴的 3 个点

### 借鉴点 1：信息"停止点"设计 → 解决日报"看不动"

**Pulse 怎么做**：每天 5-10 卡片，明示"That's it"。设计哲学是"推荐系统的价值不在让用户多看，而在帮用户少想"。

**KeyPulse 现状**：日报由 LLM 决定长度，5/7 daily 23 个 H3——没人会读完。

**借鉴落点**：日报顶部固定"今日 Top 3 Action"（用 importance_score 直接取），剩下折叠成"原料档案"。读者认知负荷砍 80%。

### 借鉴点 2：反馈直接闭环到排序权重 → 用户共进化

**Pulse 怎么做**：每张卡片 👍/👎 + Curate 指令 → 改变下轮排序权重。3-4 天可见变化。

**KeyPulse 现状**：日报完全 LLM 单向输出，无反馈通道。

**借鉴落点**：每个 H3 旁边加 markdown checkbox `[👍 relevant / 👎 noise]`（不需要做 UI，vault markdown 原生支持）。后台读取标记 → 调整 source kind 的 importance 权重。把 daily 从"算法生成"升级到"用户共进化"的**最小改动**。

### 借鉴点 3：Connector 默认关 + 粒度可控 → 信任建设

**Pulse 怎么做**：Gmail/Calendar 默认关，单独可切，每条 Connector 配"为何用它"说明。

**KeyPulse 现状**：数据源（键盘 / 剪贴板 / 浏览器 / Git）一次全开，无粒度控制感。

**借鉴落点**：HUD 加"Data Source Dashboard"——每条数据源配"为何用它"+ 单独开关。本地工具更应该卷信任，这是 vs 云平台的文化分水岭。

## 8 · Pulse vs KeyPulse 路径差异（不能直接抄的部分）

| 维度 | Pulse | KeyPulse |
|---|---|---|
| 数据 | 云端 + 闭源 connector | 本地 + 全数据源开放 |
| 形态 | 主动推送 + 卡片 | 被动记录 + 日报 |
| 节奏 | 每天主动 push | 日报/周报存档 |
| 商业 | $200/月 Pro | 个人工具 |
| 反馈 | 闭源黑盒 + 云训练 | 本地结构信号 |

**最不值得抄的**：Pulse 的"主动推送"。这条对本地 macOS 工具是**负资产**——用户已经有 HUD，再加 push 通知会变骚扰。

## 11 · Product judgment 策略建议

_由 product-judgment skill 视角输出。给建议不审判——不否决任一借鉴点，但拆开假设、找陷阱、排优先级、给最小验证步。_

### 11.1 总体策略

**不是 3 条都现在做。** Pulse 是云端订阅产品，KeyPulse 是本地工具——产品形态、商业模式、信任来源都不同。借鉴必须**拆开"机制"和"形态"**：

- 借机制：信息停止点 / 反馈进结构 / 数据源透明度
- 不借形态：主动 push / 云端 connector / 闭源排序

排优先级看 3 个维度：实现成本、L0 假设可验证性、与当前 daily 机制层升级的耦合度。

### 11.2 借鉴点 1（Top 3 Action）— P0

**Pulse 的精髓**：5 卡片 + 明示"That's it"——价值不在让用户多看，在帮用户少想。

**核心差异**：Pulse 是"推荐"（错了用户感知不到），KeyPulse 是"复盘"（错了用户感知得到——"我明明做了 X"）。所以 KeyPulse 的 Top 3 **必须可信** + **必须能下钻**。不是替换日报，是日报顶部的"快速读 + 可往下翻"。

**关键 L0 假设**：用户读日报会有"先看摘要、再看细节"的两段式行为。

**陷阱**：
- 让 Top 3 成为日报唯一入口 → 错失"档案 + retrieve"这条 KeyPulse 相对 Pulse 的核心优势
- 用 LLM 生成 Top 3 总结 → 又把价值判断丢回模型，违反 daily 刚立的"结构信号"原则

**正确口径**：
- 复用现有 importance_score / value_density 直接取 top 3 事件
- 列原始 H3 标题 + 时间，**不做 LLM 二次总结**
- 下面接现有日报全文

**最小验证（实现成本：1 小时）**：
- 改 daily 观察员 prompt，要求顶部插入"## 今日 Top 3"段，按 importance_score 降序取 3 条
- 跑 1-2 周看你自己读日报的行为变化（是只看 Top 3 还是看完全文）
- 这是 daily 改动，不是周报改动——不影响周报"先验证再设计"那个 4 周实验

### 11.3 借鉴点 2（反馈闭环）— P2

**Pulse 的精髓**：反馈成本极低 + 直接驱动结构权重 + 用户 3-4 天能感知变化。

**核心差异**：Pulse 把反馈喂给闭源排序模型；KeyPulse 应该把反馈喂给**结构字段**——这才是真正的"用户共进化"，比 Pulse 还干净。

**关键 L0 假设**：
- A1：你会主动标 H3 的 👍/👎（Pulse 真实数据：大多数用户不标）
- A2：标了之后能改对的东西（粒度问题——改 source kind 权重粒度太粗，改单事件 score 需要事件 ID 反向流）

**最大陷阱**：把反馈通到 LLM prompt（"上次用户标 X 不重要，这次别提"）→ 这就是 Pulse 反模式翻版（让模型猜用户偏好）。**反馈必须直接进结构字段，不进 prompt。**

**正确口径**：
- 标 👎 → events.db 写 `user_marked_noise=true` → importance_score 减分 / 过滤
- 标 👍 → 写 `user_marked_relevant=true` → 同 source / 同 topic 后续事件加权
- 反馈是结构信号本身，不是 LLM 提示词

**两层先后**：
- **隐式反馈先做**：用户**手动编辑/删除**某段日报内容时，自动写 negative signal——比让用户主动点 checkbox 可行得多
- **显式反馈后做**：H3 旁加 markdown checkbox 作为补充

**为什么排 P2 不 P0**：实现成本不低（需要 vault → events.db 反向流 + 事件 ID 在 H3 中可追溯）。值得做，但**先看 P0 跑 1-2 周后你日报阅读行为是什么样**——如果你根本不读日报，反馈通道也是无效投入。

### 11.4 借鉴点 3（数据源透明度）— P1

**Pulse 的精髓**：每条 Connector 单独说明"为何用它" + 默认关 + 单独可切。

**核心差异**：Pulse Connector 是"OpenAI 服务器读你 Gmail"——隐私问题。KeyPulse"数据源"是"本地进程读浏览器"——**数据不出机器**，没有隐私问题。所以 KeyPulse 借的不是"隐私控制"，是**"控制感 + 理解感"**——用户知道这个数据被用来做什么。

**关键 L0 假设**：你会在意数据源构成 / 想理解日报是从哪些数据来的。

**陷阱**：直接做"开关"——用户关了之后日报会缺什么自己不知道，关了就关了，没人提示。

**正确口径——透明度先于控制权**：
- 第一步：在 HUD 或日报顶部加一行 "今日数据来源：键盘 1023 / 剪贴板 47 / Git 12 / 浏览器 218"
- 这是**透明感**，不是开关
- 看你对这条信息的反应——是"哦"还是"为什么剪贴板这么少？"——再决定要不要做开关
- 控制权（开关）是透明度反馈出"用户想关 X"之后才做的，不是默认动作

**最小验证（实现成本：HUD 加一行）**：1 小时改动，看 1-2 周你对数据源构成的反应。

**为什么排 P1**：实现极便宜，能借 Pulse 的"信任建设"哲学。但优先级低于 Top 3，因为 Top 3 直接改日报体验，数据源透明度只是辅助信号。

### 11.5 优先级总表

| 借鉴点 | 实现成本 | 关键 L0 假设 | 优先级 | 与 daily 升级耦合 |
|---|---|---|---|---|
| Top 3 Action | 1 小时（prompt 改动） | 用户读日报有两段式行为 | **P0** | 强（直接复用 importance_score） |
| 数据源透明度 | 1 小时（HUD 加一行） | 用户在意数据源构成 | P1 | 弱（独立模块） |
| 反馈闭环（隐式） | 中（vault→DB 反向流） | 用户会编辑日报 + 编辑能反馈结构 | P2 | 中（事件 ID 需在 H3 可追溯） |
| 反馈闭环（显式） | 中（同上 + checkbox 解析） | 用户会主动标 | P3 | 同上 |

### 11.6 陷阱排雷清单（不要做的事）

- ❌ **主动 push 通知**——和现有 HUD 冲突，会变骚扰，是 Pulse 形态特有，本地工具负资产
- ❌ **反馈喂给 LLM prompt**——Pulse 反模式翻版，违反"价值判断走结构信号"
- ❌ **个性化深度调节滑块**——把判断丢给用户的伪能动性
- ❌ **Top 3 用 LLM 二次总结**——又把价值判断给模型
- ❌ **数据源直接做开关，不先做透明度**——用户不知道关了会缺什么

### 11.7 核心原则映射

| Pulse 的设计 | KeyPulse 借不借 |
|---|---|
| 反馈→结构权重 | ✅ 借（且要比 Pulse 更彻底——不进 prompt） |
| 反馈→LLM 揣摩 | ❌ 不借 |
| 主动 push | ❌ 不借 |
| 信息停止点 | ✅ 借（Top 3） |
| 隐私粒度控制 | ✅ 借（但语义换成"透明度先于控制权"） |
| 闭源排序算法 | ❌ 不借（结构信号优先） |
| 云端 + 订阅 | ❌ 不借（本地优势保留） |

- [ ] **本周内**：HUD 加"今日数据来源"一行（1 小时改动），观察反应
- [ ] **2 周后**：根据 Top 3 + 数据源透明度的真实使用反馈，决定是否启动反馈闭环（P2）

---

> **核心建议一句话**：Pulse 最值得偷的不是"主动推荐"，是"反馈直接进结构 + 信息停止点"。这两条恰好对应 KeyPulse 已经在 daily 上立住的"结构信号 > LLM 判断"原则——**借的是同一个产品哲学的更进一步**，不是新方向。
